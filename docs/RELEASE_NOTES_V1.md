# Version 1 release notes — candidate `v1.0.0`

This is a **proposed designation**, not a Git tag or a released deployment. The Laravel web/API implementation includes approval-gated accounts; role- and permission-based administration/delegation; requester and FMO personnel profiles/skills; campus/building/location reference data; Work Order requests with private attachments; screening, clarification, approval/disapproval and Campus Director direct authorization; multiple-person assignment; assessment and management exception review; individual work sessions, updates, evidence, continuation/waiting states, completion and verification; in-app notifications; dashboards, scoped history, CSV and browser-printable Work Orders.

The Flutter source contains a per-account SQLite task cache and durable outbox, secure token storage, assigned-only full snapshots, idempotent server operations/media uploads, conflict-preserving retries, a basic notification list/read view, and copyable issue details. Queue ordering now holds later actions behind earlier unresolved work on the same order. Account ID and token are stored as one record to avoid split-key account mixing after an interrupted write; existing legacy credentials require same-account online sign-in, with local data retained. **These latest mobile changes have not passed Flutter SDK, Android build, device, restart/offline, or account-switch verification in this workspace.** The Android platform project is absent; backup exclusion and device policy remain a technical gate before use with real field data. Native OS background scheduling and full media conflict export are not implemented; exact-hourly delivery is not guaranteed.

Version 1 does not include inventory/material stock deduction, tools, asset/QR management, preventive maintenance, recurring inspections, push notifications, advanced BI, or AI-assisted decisions. Potential Version 2 modules should be planned separately; none are part of this candidate. Backend hardening added private upload rollback cleanup, personnel-history delete protection and inactive-personnel read-scope protection. Formal human UAT and shared-hosting validation remain required before pilot, but do not alone make development implementation incomplete. See [release readiness](RELEASE_READINESS_V1.md) for the current test result and separate mobile technical gate.
